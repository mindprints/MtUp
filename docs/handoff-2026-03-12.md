# Handoff - 2026-03-12

## Session Summary

This session moved MtUp from local-only orchestrator assumptions to a real Vercel deployment path, fixed multiple production/runtime mismatches between localhost and Vercel, and tightened the Snooky activity card UI so the activity feed is closer to the intended production UX.

By the end of the session:

- `mtup.vercel.app` was linked and deployed from this repo
- the orchestrator can run as Vercel Node functions
- Vercel and localhost behavior were brought back into sync for the main Snooky flow
- the activity cards were cleaned up substantially

### 3) Production Runtime / Env Parsing Fixes

- Fixed client env parsing bug that caused deployed app to come up as:
  - `data source: local`
  - `ai assistant: disabled`
- Root cause was whitespace-sensitive env parsing in runtime config.
- Fixed server env parsing similarly so orchestrator env values are trimmed before use:
  - `OPENROUTER_API_KEY`
  - `OPENROUTER_MODEL`
  - `OPENROUTER_BASE_URL`
  - `SUPABASE_URL`
  - `SUPABASE_ANON_KEY`
  - mail envs
- This was necessary because Vercel and localhost were not behaving the same until the parsing was hardened.
- Files:
  - `src/lib/runtimeConfig.ts`
  - `server/dev-orchestrator.mjs`

### 4) Snooky Proposal Intent Fixes

- Fixed proposal classification gap where prompts like:

  were not reliably treated as proposal requests.
- Broadened deterministic proposal heuristics to include travel/sejour terms and month/weekend phrasing.
- Added server-side test coverage for proposal intent classification.
- Updated Vitest config so server tests are included in normal runs.
- Files:
  - `server/dev-orchestrator.mjs`

### 9) Activity Stack Jump Fix

- Fixed bug where editing a proposal card would jump the feed back to the first card.
- Root cause:
  - proposal cards were keyed with `proposal.id + proposalFeedRefreshTick`
  - refresh tick increments forced card remounts
  - remounting reset feed position
- Removed the remount pattern and stale refresh state.
- Files:
  - `src/components/AiAssistantPanel.tsx`
  - `src/components/ai-assistant/ProposalCard.tsx`

- `vercel.json` now forces correct build/output behavior, so deployment works.
- But project-level settings in Vercel UI may still be worth cleaning up manually.

3. **Card UI still has readability work on bright images**
- Overlay content is better now, but contrast/readability on light thumbnails still needs a dedicated pass.

4. **Activities card layout can still be tightened**
- Pills are cleaner now, but there is still room to rebalance the body area around notes/alternatives/plan without making cards feel busy.
