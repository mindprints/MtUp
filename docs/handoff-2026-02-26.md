# Handoff - 2026-02-26

## Session Summary

This session shifted MtUp further into a Snooky-first planning flow.  
The proposal experience in `What's Up?` is now postcard-oriented with dominant thumbnails, compact participant state avatars, and attributed alternatives via a single modal.

The assistant and memory system are now practical for iterative testing with seeded fictional personas.

- Reduced formal/system-heavy copy in cards.
- Removed explicit feed scaffolding text/pills that felt redundant.
- Added compact avatar state strip:
  - green = in
  - amber = suggested alternative/date
  - gray = waiting

  - `src/components/AiAssistantPanel.tsx`

### 5) Thumbnail Storage Quota Mitigation

- Encountered browser localStorage quota error with base64 thumbnails:
  - `"Failed to execute 'setItem' ... exceeded the quota"`
- Implemented eviction-on-quota behavior in thumbnail storage:
  - oldest thumbnails are removed until write succeeds.
- This is a mitigation, not final architecture.
- File:
  - `src/lib/proposalThumbnailStore.ts`

## Known Risks / Gaps

1. **Local-only persistence for new Snooky artifacts**
- Proposal contributions, memory, and thumbnails are localStorage-backed (not server persisted yet).

2. **Storage quota pressure**
- Base64 thumbnails are heavy; localStorage remains fragile despite eviction.
- IndexedDB or server/object-storage should replace this.

3. **Client-side API key exposure**
- Thumbnail generation currently runs in client code using `VITE_*` env key.
- Better long-term approach: server-side proxy endpoint using trusted key.

4. **Workspace divergence**
- Workspace UI is now behind Snooky in maturity and may be deprecated.
- Navigation and ownership between surfaces need product decision.
